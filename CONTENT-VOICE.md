# Content voice — The Stewardship Standard

Normative spec prose uses formal, precise language per each spec's conventions. Overview and contributor-facing docs should remain clear and systems-aware without hype.

## Public-facing summaries

When writing README sections, CONFORMANCE.md summaries, or issue templates:

- Clear, precise, calm, accountable
- No guarantees or certification claims unless attested per SCA process
- Plain language in QSM-OVERVIEW; formal definitions in normative specs

## Agents

Load `brand-style.json` for voice defaults. Normative edits must follow `GOVERNANCE.md` and `CONTRIBUTING.md` — not editorial preference alone.
